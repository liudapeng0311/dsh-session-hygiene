# dsh-session-hygiene

[English](https://github.com/liudapeng0311/dsh-session-hygiene/blob/main/README.md) | 中文

一个插件，补上 DSH 侧边栏的三个缺口：

1. **会话只能归档，不能删除。**「删除会话（移入回收站）」把日志移出会话
   存储放进回收站，而不是直接 unlink，所以还能还原。
2. **删除工作区会把它的会话留在磁盘上。**这些会话的 `cwd` 已经对不上任何
   工作区，侧栏没地方显示它们。**设置 → 会话清理**能把它们找出来，归档或
   移入回收站。
3. **工作区没法分组。****设置 → 工作区分类**提供分类、侧栏分类标题、拖拽
   归组和折叠。

全部是增量改动：不替换、不隐藏任何自带行，也不重写这些组件以外的 DOM。

## 它出现在哪

| 位置 | 你会看到什么 |
| --- | --- |
| 会话行 `...` 菜单 | **删除会话（移入回收站）** |
| 侧栏工作区列表 | 分类标题，拖拽归组 |
| 设置 → **会话清理** | 孤儿扫描、回收站、还原、彻底删除 |
| 设置 → **工作区分类** | 分类、归属、排序、标题开关 |

## 安装

从 npm 装，走 DSH 的 **Plugins** 页面，或者直接让 agent 装：

```
plugin_manager install_bundle dsh-session-hygiene
```

装本地 checkout 的话，传它的绝对路径：

```
plugin_manager install_bundle <当前 checkout 的路径>
```

宿主侧 JavaScript 不热重载：装完重启一次宿主。

## 删除一个会话

1. 在侧栏指向某个会话，打开它的 `...` 菜单。
2. 选 **删除会话（移入回收站）**。
3. 这一行立刻消失；数据是被移动了，不是被删除。

内部按这个顺序做：停掉正在跑的工作并隐藏该行 → 把它从所有工作区 detach 并
取消置顶 → 把 `<home>/sessions/<group>/<id>/` 重命名进回收站 → 记一条
`preview` → 发 `api-session/removed`，已经打开的页面不用刷新就会移除这一行。
投影缓存会保留，所以还原之后标题和开场提示都还在。

如果移动失败并提示 **「会话数据仍被占用。先切到另一个对话，再回来删除。」**，
说明还有别的视图开着这个目录：切到另一个对话再重试。移动失败时归档会回滚，
会话仍按原样显示。

## 清理被删除工作区遗留的会话

打开 **设置 → 会话清理**。页面打开就会扫描一次；**重新扫描**可以重来。

**孤儿会话**指的是磁盘上还在、但 `header.cwd` 对不上任何已注册工作区的会话。
每一行显示标题、开场片段、原本属于哪个工作区、目录名和体积。

- 行内：**移入回收站**。
- 批量：**归档 N 项** —— 收进宿主自己的归档列表，会跳过子代理会话，因为
  它们通常由父会话持有。
- 批量：**全部移入回收站** —— 包含子代理，操作前要确认一次。

**未挂载**是另一类情况：会话的 `cwd` 对得上某个工作区，但那个工作区没把它
列进去，于是侧栏把它归到「未分组」。这类会话会在标签页上方单独出一条提示，
配一个 **全部挂回** 按钮——比直接删掉一个本身健康的会话更划算。

## 回收站：还原或彻底删除

**回收站**标签页列出已经移进去的内容。

- **恢复**会把目录重命名回它记录的原始路径，并按 `cwd` 重新挂回对应的工作区。
  如果原位置已经被占用，会拒绝操作（`409`）——先移走或删掉占位的东西。如果
  原工作区已经不存在了，会话会回来，但显示为未分组，因为已经没有东西持有它的
  `cwd`。
- **彻底删除**会删掉目录，并清掉它的投影缓存。这是唯一不可逆的操作，而且它
  每次都明确指名删哪些；需要再点一次确认。

批量操作对应 **全部还原** 和 **全部彻底删除**（后者要求确认条数）。

## 给工作区分组

打开 **设置 → 工作区分类**。

- **新增分类**，行内改名，用 **上移** / **下移** 调顺序，**删除**（被删分类
  下的工作区回到未分类）。
- 用下拉框给工作区选分类，或者直接把侧栏的工作区行**拖到分类标题**上。
- **保存并聚拢** 会写入归属并重排工作区注册表，让同一分类的行连续；未分类的
  排在最后。宿主自带的行拖拽排序照常可用——这里只在保存时重排一次。
- **清空归属** 把所有工作区退回未分类，但保留分类本身。
- **分类标题右侧的 +** 会打开宿主的目录选择窗口，把选中的目录登记为工作区，
  直接归到这个分类下并聚拢到位。
- 点分类标题可以折叠或展开，折叠状态会持久化。折叠时，分类下每个长列表末尾的
  **展开其余 N 个会话** 也会一并收起，所以折叠后屏幕上只剩分类标题。
  **在侧边栏显示分类标题** 可以整组隐藏标题，归属关系不受影响。

分类下的行会内缩一级，让标题看起来是它们的分组，而不是同级项。分类只有在它的行
**连续成块**时才会显示标题；被拆散的分类不显示标题，而不是把标题画到属于别处的
行上方。标题带和内缩都是插件自己加的改动，卸载时会一并还原，侧栏回到宿主原本
渲染的样子。

## 数据在哪

```
<home>/storages/session-hygiene/
  categories.json
  trash/<sessionId>__<stamp>/
    entry.json
    session.v4.jsonl.zstd ...
```

`entry.json` 记录 `sessionId`、`cwd`、`from`（原始目录）、`title`、`preview`、
`createdAt`、`sizeBytes` 和 `deletedAt`。它是这个插件唯一自己写的文件，也是
能还原的原因。

想手工清空回收站，直接删掉那棵目录树即可。投影缓存是故意在移入回收站时保留
的（它是派生数据，保留才能让还原后的会话仍然显示标题），彻底删除时才清掉。

## 卸载

在 DSH 的 Plugins 页面移除这个 bundle。侧栏会立刻失去分类带，也没有任何自带
行会停留在被改过的状态。

**先把回收站清空或还原完。**卸载后 `<home>/storages/session-hygiene/` 会留在
磁盘上，但已经在回收站里的会话不再有任何界面能还原它们——只能照着各自的
`entry.json`，手工把目录改回原路径。

## 已知限制

- 孤儿判定是拿会话的 `header.cwd` 和注册表里记录的工作区目录做比较。如果一个
  会话的 `cwd` 在磁盘上被改过名，它会被判成孤儿，哪怕工作区其实还在。
- 删除工作区时依然不会提示它还有多少会话；这个插件只能在事后、在设置里把它们
  列出来。想在删除那一刻拦截，就得接管 `sidebar.workspaces`，而那是宿主自己的
  `single` 槽。
- 子代理会话会被列出并单独标记，**归档 N 项** 会跳过它们，批量移入回收站则
  包含它们。
- 分类标题依赖行连续；把一行拖到**两行之间**时，它的分类是从上方标题推出来的，
  当一个分类只有一行时这只是个猜测。
- 分类标题的 **+** 依赖宿主的原生目录选择能力（`directoryPicker` 的 `native`）；
  只有浏览模式的 profile 会被拒绝并提示，不会打开浏览器里的选择器。
- 宿主侧 JavaScript 不热重载：安装或更新后重启宿主。

## 开发

```
node tests/host-smoke.mjs
```

这个冒烟测试用真实的请求处理器，把一个临时 `DSH_HOME` 从头跑到
scan → trash → restore → purge，不会碰任何真实 profile。它通过 `files` 排除
在发布包之外。

| 槽 | Id | 用途 |

| `settings.section` | `workspace-categories` | 分类页 |
| `settings.section.icon` | `session-hygiene`、`workspace-categories` | 导航图标 |
| `sidebar.footer.action` | `session-hygiene-labels` | 本身不渲染，只挂载画分类带的 DOM 观察器 |
